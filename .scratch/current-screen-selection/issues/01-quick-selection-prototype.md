# 01：验证本屏快速选窗交互

Status: needs-info
Progress: in-progress

## What to build

提供可操作的网页原型，体验 B 每次进入本屏选窗模式、按标记及标题候选选择、预览、确认、取消和恢复。设计依据见[设计记录](../spec.md)。

Blocked by: None

## Acceptance criteria

- [x] 可见窗口与完全遮挡窗口均可选择，选择顺序可见。
- [x] 选择、切换预览、取消均保持实际模拟几何；确认只移动所选本屏窗口。
- [x] 再次 B 进入选择模式；取消保留已有布局及恢复记录。
- [x] 零窗或一窗选择不能执行；A 与 B 保持副屏窗口不变。
- [x] 鼠标、键盘及四个引导场景可操作，网页无运行错误。
- [ ] 用户体验后给出交互结论，再细化正式实现规格。

## Comments

用户已确认 B 每次触发进入选窗模式、Enter 确认、Esc 取消。此前“有组直接执行”建议不再沿用。原型使用模拟桌面，不验证真实 Win32、系统快捷键或任务效率；生产程序本轮未变更。

原型已完成浏览器检查：28 项检查通过，0 失败，无运行错误。检查使用实际网页点击与按键，通过 getBoundingClientRect 读取渲染边界并转换为文档坐标，按 0.001 CSS 像素精度比较；副屏同时比较 DOM 与渲染边界。覆盖全遮挡窗口标题选择、零/一窗拒绝、重复 B、选择与预览不改位置、取消保留恢复记录、确认及恢复、另一屏不变、四个引导场景、宽窄视口。宽窄截图均已读取，无横向溢出，窄屏以纵向排列保留副屏对照。这些结果仅适用于网页模拟。

预览与 HTML 入口见[设计记录](../spec.md)。原型仍待用户体验；本轮未提交或发布。

用户后续反馈“okay, 看着不错”。记录为原型外观方向认可，尚未收到四个场景的逐项操作反馈；最后一项人工体验条件保持未勾选。分诊改为 needs-info，表示等待操作体验信息，不表示需要人工实施。外观认可允许继续起草规格与任务拆分，不代替原生验收。

[规格草案](../spec.md)已补全设置、本屏保护、B 选择与焦点、失败和恢复规则；[任务草案](../implementation-plan.md)拟分为设置、A 与共享本屏保护、B 原生选窗三个增量。正式任务尚未发布为 ready-for-agent。

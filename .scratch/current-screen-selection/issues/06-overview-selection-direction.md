# B：统一呈现本屏窗口的交互方向

Status: ready-for-agent
Progress: done

## 目标

用户希望改进 B：可见窗口点桌面标记、遮挡窗口另开“所有窗口”的两条选择路径产生额外操作成本，考虑新的交互方式。

## 已确认方向与待定细节

进入触发时捕获屏幕的窗口总览，将所有现有合格候选统一为可多选卡片。应用名、完整标题、选中编号是基本信息，内容缩略图为增强；不可获取缩略图时卡片仍可选择。最小化窗口、其他虚拟桌面等范围不扩大。

点击切换选择，合格前台默认 1 号；每次新选择、Enter 排布、Esc 取消沿用。只在呈现中展开卡片，确认前不移动真实窗口，不改已有 Undo。身份/屏幕/工作区复验、操作互斥和焦点失败退出保持。

用户已选择统一本屏总览，内容预览为主要辨认信息、应用名和标题辅助。已接受推荐的方案 1「统一网格」，不推进另两种主视图；候选稳定排序、右侧前移/后移调整顺序、滚动与搜索浏览已获确认；不再沿桌面旁候选栏方向推进。效率需要通过真实两窗/三窗选择任务比较，不宣称已经更快。

## 已确认的组织与操作规则

- 进入时合格前台第一，其余按原桌面上到下、左到右；点击选择及标题变化不重排卡片。
- 选择顺序产生编号；右侧已选列表可前移、后移，更新编号和布局预览，不改变左侧卡片位置。
- 多窗口保留可辨认卡片尺寸，纵向滚动；按应用名、标题搜索，筛选不移除已选成员，右侧始终保留它们。排布操作持续可达。

Q1–Q6 已确认，用户随后回复「认可」，授权按规格进入原生验证与实现。设计任务已收口，实施和运行证据由任务 07 跟踪。真实缩略图的官方接口已核对，WPF 宿主、遮挡内容和第三方应用的原生兼容仍待探针验证；网页原型只能检验流程，不能证明 Windows 内容预览和输入能力。A 和跨屏大列表沿用当前行为。

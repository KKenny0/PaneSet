# 跨屏选组、多窗布局和快捷入口

## 目标

按用户的多显示器和更多窗口反馈，扩展已有 Windows 原型：从当前虚拟桌面的连接屏幕选出至少两扇窗口，明确选择目标屏幕，集中排布并恢复各窗原状态。

## 行为

- 普通及最大化的可调整大小顶层窗口可选；遮挡不排除，最小化、隐藏、全屏、附属、其他虚拟桌面窗口排除。
- 选择顺序决定位置，刷新按完整身份保留存活选择和顺序，切换目标屏幕不清空选择。
- 自动布局在两三窗使用等宽列，四窗起使用网格；另可选择等宽、一主多辅和网格。主窗为 1 号，多窗轮换把 1 号移到末尾。
- 12 物理像素间距；任何格子小于 240 × 160 时移动前拒绝。
- 首次修改前保存整组快照。只对受影响且身份有效的目标恢复各自来源屏幕、大小、位置、正常或最大化状态；失败保留记录。
- Ctrl+Alt+Space 打开或收起，Ctrl+Alt+Z 恢复；独立注册并提示冲突。最初考虑的 Ctrl+Alt+P 在本机返回注册冲突，已替换。
- 全局唤起默认选中合格的前台窗口，以其屏幕为目标并定位面板；不合格时回退鼠标所在屏幕和空选择。
- 收起、关闭和 Esc 保留进程及恢复记录；明确退出释放注册。重复启动唤起已有面板，即使面板已有焦点也保持打开。
- 尚未完成的操作禁止冲突排布和恢复；等待不等于取消。

## 验证与交付标准

仅移动 fixture 自建的真实 Windows 窗口。覆盖双向跨屏、正常和最大化恢复、三窗主辅、八窗网格、未选窗保持不变、身份、部分失败、等待、顺序及真实客户区边界。单实例用真实应用进程验证。

快捷键的实际按键路径与消息处理分别检查。合成 WM_HOTKEY 只验证 hook、面板恢复和操作保护，不能替代系统按键送达证明。实际按键检查成功注入后若未达到恢复及前台条件，仍是失败；仅 SendInput 完全未插入且返回错误 5、架构不适合或注册被占用时报告无法验证。

当前实现和检查结果见 [验收记录](../../docs/VALIDATION.md)。实际快捷键完整验收尚未完成，任务不标记 done。

## 已确认的 Q1、Q2 设计增量

确认依据：用户先接受 Q1 大列表方向，随后明确回复“那就按这个收敛范围确定 Q2”。本节是已确认设计与首版规格约定，两个增量现已实现并完成各自 /check 范围审查；最新运行证据与未验收项见验收文档，不能用设计确认替代实际通过。

### 增量 A：大列表与局部布局键

对应[任务 02](issues/02-picker-and-layout-keys.md)。该增量在没有最近组功能时也可完成选窗、排布及恢复。

- 保留同一个面板。搜索与窗口列表主导，宽窗口左列表、右布局与紧凑预览；窄窗口默认折叠预览。正常尺寸以同时查看 6 至 8 扇普通短标题窗口为目标；长标题保留换行、完整搜索及提示。
- 首版规格固定 Alt+1 等宽并排、Alt+2 一主多辅、Alt+3 网格，在对应选项旁显示提示。局部键只更新预览，Enter 或排布按钮才修改窗口；普通数字输入、中文输入和搜索不触发布局。
- 保留自动布局、Ctrl+F 搜索、Alt+S 轮换和 Esc 收起；不增加全局布局键。
- 普通全局唤起仍从合格前台窗口开始新选择；自身前台时全局键收起。重复启动只打开面板，自身前台时保留当前选择，不收起。
- 沿用 MainWindow 的选择与控件更新、LayoutEngine 的现有布局和 WindowManager 的原生排布及恢复。仅为局部键增加同一布局选择入口，不新增命令服务、配置项或运行依赖。

### 增量 B：最近窗口组

对应[任务 03](issues/03-recent-window-group.md)。沿用同一面板，加一个“调整最近组”按钮；增量 A 的选窗和排布流程保持可用。

- 仅保留一个当前进程内的最近组，记录完整窗口身份、顺序、目标屏幕及布局。记录由面板负责，恢复快照继续由 WindowManager 负责；不引入持久存储或新的公共窗口操作接口。
- 在排布请求开始时留存本次选择与目标；操作处于等待状态时保留这份请求。只有收到整组最终成功结果才发布为最近组，包括延迟完成的成功。最终失败、部分失败或无效请求不更新最近组。无原记录时按钮不可用；收起保留，明确退出清除。
- 成功但窗口状态没有实际改变的请求可以更新最近组元数据，保留原恢复记录。部分失败后的恢复继续覆盖本次实际受影响窗口，与之前的最近组记录独立。
- 载入时刷新屏幕和候选，清除搜索筛选，按完整身份匹配当前合格窗口，以当前标题显示，保留相对顺序。载入和预览不移动窗口，也不读取旧恢复快照作为下一次恢复依据。
- 关闭、身份变化、最小化或其他候选条件失配时，明确说明缺失成员并保留有效成员供检查、补选或减少选择。不得用同应用其他窗口补位；有效成员不足两扇时禁止排布。
- 原目标屏幕不可用时，不自动转到另一屏幕执行；目标保持未确认，用户重新选择后才能排布。原屏幕仍可用但工作区域改变时，使用当前区域重新预览并显示目标，由正常排布操作确认。
- 实际执行前再次校验身份、当前桌面、候选资格及屏幕环境，首次修改前读取整组最新状态。载入后手动移动窗口，再次排布的恢复依据是此次修改前的实际状态。
- 恢复最近一次有实际影响的排布；例如状态 S0 → 等宽 S1 → 主辅 S2，恢复回 S1。载入、预览、失败的预检或没有实际影响的请求不清除旧恢复记录。
- 正在操作或等待期间，最近组载入、布局切换、排布和恢复共用既有保护；700 ms 仍仅为反馈阈值，不丢弃未完成请求。

### 验收路径

| 路径 | 判定 |
| --- | --- |
| 正常选组 | 两窗、三窗与八窗可搜索、多选及检查顺序；每种局部键只改变预览，确认后原生读回预期位置，未选窗口不变。 |
| 面板与输入 | 正常尺寸检查可见行数；600 × 730、820 × 600、600 × 600 及长标题检查预览折叠、滚动、反馈和按钮客户区边界。搜索输入普通数字、中文时不误触发；已有键位继续工作。 |
| 最近组成功复用 | 三窗跨屏排布成功后载入，恢复成员相对顺序、目标和布局；载入与切预览不改变实际几何、最大化状态或恢复记录。 |
| 身份与候选失效 | 同应用多窗、标题变化、关闭或句柄复用、最小化及其他桌面成员分别检查；不替换错误目标，缺失说明可见，少于两扇不能执行。 |
| 载入后发生变化 | 载入后再关闭窗口或改变身份，实际执行仍拒绝过期目标；手动移窗后再次排布，再恢复到此次排布前的新状态。 |
| 屏幕变化 | 原目标不可用时禁止自动转屏排布；重新选择后更新预览。工作区改变时使用当前区域。真实断屏及混合 DPI 仍需受控显示环境，未完成时单列未验证。 |
| 部分失败与等待 | 保留之前最近组及当前受影响窗口恢复记录；等待不提前发布最近组，终局成功才更新。等待时重复按键、载入、排布与恢复不启动冲突修改。 |
| 无变化与连续排布 | 成功但窗口状态没有实际改变时，可更新最近组并保留旧恢复记录；连续两个有实际影响的布局后恢复到第二次修改前，不回到 S0。 |
| 生命周期 | 普通唤起新选组、主动载入最近组、自身前台全局收起、重复启动保留选择、关闭仅收起及退出后重启无记录分别验证。 |

实现后先运行相关界面、布局与原生定向检查，再运行 `verify.cmd` 和 `tools/run.ps1 --probe`。新交互检查并入既有检查程序；命名与输出须区分真实系统按键和合成消息。人工验收局部布局键及实际全局唤起、恢复，记录实际按键、面板出现和获得焦点的结果。不能以截图或 WM_HOTKEY 路由通过代替真实输入验收。

实施将涉及已有 UI、交互检查、规格与验收文档、多尺寸截图，合计可能超过 8 个文件，不新增服务。仅自动移动 fixture 自建窗口；不自动提交、推送或发布。代码回退不需要迁移数据；已排布窗口须在记录仍有效时使用恢复，退出后不能声称可以重建记录。

### 价值验证与排除范围

最近组的价值假设是同组会重复调整。由真实任务试用记录同组复用频率、完整点击及按键次数、耗时、修补与恢复成本。实测收益由后续使用结果判断；第三方兼容、混合 DPI 和实际全局键失败继续由实现与验收阶段验证，不以本次设计定稿代替。

首版排除独立弹窗、多组保存、应用启动、自动取最前几窗、跨进程匹配及额外全局直达键。每个增量完成后更新其任务与验收记录；最新隔离完整检查通过，但历史实际输入不稳定的根因未确认，原任务 01 继续保持 in-progress。

## 范围外

macOS、长期窗口组、持续联动缩放、跨虚拟桌面、最小化窗口唤醒、显示配置变化后的自动迁移、托盘和开机启动。混合 DPI 与第三方应用的兼容性仍需真实验证。

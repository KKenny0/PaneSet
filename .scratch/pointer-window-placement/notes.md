# 指向辅窗的单窗放置：设计讨论

## 已接受的决定

- Q1：常用入口采用 A。保持临时窗口激活，鼠标指向有可见部分的辅窗，按一次现有快捷键直接借用其当前位置和大小。完全被遮挡的目标使用备用选择入口。
- Q2：目标区域短暂描边，直接执行，无额外确认步骤；反馈自动消失，正常完成后源窗口保持激活。
- Q3：鼠标落在源窗口自身、桌面、任务栏或其他无效目标上时，轻提示并保持窗口不动。不猜目标，不自动打开选择面板。
- Q4：现有列表与位置预览降为备用选择器，从主面板“选择其他位置…”按钮打开。

沿用此前已确认的行为：源窗口匹配参照窗口的可见边界；参照窗口留在后面；仅恢复实际改变的源窗口。不要求先有 PaneSet 排布记录，沿用用户配置的快捷键。

## 收敛后的设计

完整产品规则及边界见 [规格](spec.md)。设计与规格整理阶段没有开始实现；用户随后调用 `implement-spec`，现已完成直接指向入口的代码，列表与空间预览保留为备用。当前验证及未验收范围见 [实施记录](implementation.md)。运行实例未替换。

Loop 仅作为用户对交互感觉的类比，不从中推定长按、松手提交、双击触发或额外全局手势。

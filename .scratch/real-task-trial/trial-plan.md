## 三项任务

使用当天已有的真实文件和窗口。开始前简记应用、窗口标题、来源屏幕/缩放和起始位置。每种方法使用相同窗口、内容和完成目标；复原起点所需准备不计入排布时间，但另记准备成本。

| ID | 任务与完成标准 | PaneSet 当前执行路径 |
| --- | --- | --- |
| T1 | 从多个窗口中找到同应用的两份文档，并排查看，找到一个实际差异；结束后恢复原位置 | 当前文档上打开主面板，补选另一文档，等宽排布；记录找窗、顺序修补和恢复 |
| T2 | 浏览器、PDF、编辑器三窗，至少一窗初始在另一屏；查到一项资料并在编辑器中使用，三窗可读；结束后恢复 | 主面板跨屏选三窗，选目标屏；按任务选等宽或一主多辅；观察是否还需改尺寸或顺序 |
| T3 | 先有已排好的主辅窗口，再开一扇临时资料或工具窗口，放到指定辅窗区域使用，之后回到原任务；其他窗口位置大小不变 | PaneSet 路径：按住拖动辅助键（本机现配置 Ctrl+Shift）拖临时窗口标题栏入格松手，位置与大小一步就位（0.3.0 拖动投放）。记录操作步数与修补；拖动清单 #14 等项仍留后续，试用结果不代验收 |

T3 需记录原辅窗是否仍需同时可见、是否被不希望地遮住、结束时如何重新看到原辅窗、临时窗回到哪里。它检验新需求的使用成本，不是尚未实现功能的验收。

## 比较对象与顺序

必测对象：用户现行办法、当前已核验版本 PaneSet、Windows 原生 Snap。若现行办法就是 Snap，只记录一次并标为相同方法，不制造重复样本。

原生 Snap 起点为激活目标窗口，再使用 Windows + 方向键或用户熟悉的拖动/Snap Assist 路径。不将 Windows 11 的布局弹层假定为本机可用。T2 若不能直接得到所需比例，允许手动修补并计时；无法满足完成标准就记未完成。

FancyZones 是可选补充，尚未核对安装版本与配置，也未操作；预检没有发现其运行进程，不据此认定未安装。不为本轮自动安装或更改其配置。若以后补测，记录版本、区域设置与首次配置时间，日常耗时单独计算。

顺序采用：T1 现行办法 → PaneSet → Snap；T2 Snap → 现行办法 → PaneSet；T3 PaneSet 现有路径 → Snap → 现行办法。每种不熟悉的方法先允许一次不计时熟悉，记录是否做过；这只能降低顺序影响，不能消除学习效应。

先各做一次真实任务，发现分歧才针对该项复测，不重复已有功能验收清单。一次样本不用于宣称稳定更快。

## 记录方法

使用秒表或系统计时即可，无需录像或新工具。不要按估计填写秒数；没计时写“未计时”。把执行命令、点击或按键组合按用户动作记数：一次点击、一次快捷组合分别算一次，输入连续搜索词算一次输入；持续拖动算一次，另计找窗造成的焦点切换。

- 排布耗时：从开始找窗口，到布局满意且能开始工作。包括选窗、焦点切换、预览和修补，不包括阅读或编辑正文的工作时间。
- 返回耗时：完成内容工作后，从开始返回原任务，到原任务重新可用。分别记录恢复窗口几何和重新看到原辅窗，二者不混为一谈。
- 错误与修补：误选、漏选、布局比例不合适、应用拒绝尺寸、需要再拖动、失败提示是否可理解。
- 最近组：是否真的点击“调整最近组”，用了几次，以及省去了什么；不要求为了测它而使用。
- 日常频率：之后自然遇到 T3 时记一笔即可，区分“用户说高频”与“本轮实际次数”。

记录表见 [results.md](results.md)。每条尽量写“做了什么 → 发生什么 → 多做了什么”；不需要暴露工作文件内容。

## 如何形成下一步建议

已知证据是用户真实使用中提出单窗放置，接受四项核心规则，并补充现行路径为鼠标拖动后保持大小或按需手动缩放。当时的优先候选"一次位置选择同时应用位置与大小"已由 0.3.0 拖动投放实现（人工清单部分项仍留后续）；计时和竞品实测仍缺，不能声称它节省了多少时间。

收到记录后，先按发生频率、对原任务的干扰、放置及返回步骤排序。若 T3 反复需要手工搬窗且无须其他窗口重排，优先做单窗放置的最小增量；若主要成本仍在找窗或辨认同应用窗口，先处理该处。已有最近组保持现状，未观察到实际使用收益前不追加能力。

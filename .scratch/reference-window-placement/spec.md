# 单窗放置：借用已有窗口的位置

## 授权与旧规格的关系

用户指出单窗放置依赖先前的 PaneSet 排布，无法冷启动，并确认“先做前一种”：借用已摆好辅窗的当前位置和大小。本规格对新模式的规则取代 `.scratch/single-window-placement/spec.md` 中“只能来自 PaneSet 历史布局”的前提。旧规格的已保存坐标语义继续适用于显式选择的“上次布局位置”。不改写旧文档中的历史决定与验证结果。

## 用户流程

1. 从要放置的临时窗口触发现有“单窗放置”动作，默认绑定仍为 Ctrl+Alt+3；自定义、禁用和主面板按钮继续生效。
2. 默认打开“借用窗口位置”。列出当前桌面所有连接屏幕的合格窗口，排除源窗口。显示固定编号、窗口标题、应用名、来源屏幕和参考尺寸。
3. 支持按应用名或标题搜索；Ctrl+F 聚焦搜索。搜索框内的数字属于搜索文字，筛选保留原编号。列表内独立按 1–9 或小键盘编号选择对应可见项，10 及以上通过点击或 Tab 后 Enter / Space 选择。
4. 提交后，执行器重新读取所选参照窗口的当前可见边界，将源窗口移动并缩放到该矩形。参照窗口原有显示状态不复制给源窗口；源窗口在目标矩形上使用普通窗口状态。
5. PaneSet 只对源窗口发出修改请求。参照窗口留在后面；Undo 沿用同一恢复入口，只还原本次实际改变的源窗口。应用或系统仍可能引发其他窗口的连带变化，不承诺 Windows 原子事务。

有历史位置记录时显示“上次布局位置”入口，保留原有比例图、编号和固定保存坐标。切换入口不修改窗口、不生成历史或 Undo。没有记录也能直接借用位置；没有其他候选时说明原因，允许取消和重新唤起。

## 固定来源与执行保护

- 源窗口身份在唤起前捕获，选择参照时不替换源窗口。主面板继续显示当前可用来源。
- 每次唤起固定候选顺序、编号和身份，不根据标题、搜索结果或焦点重新编号。关闭或失效项不自动匹配成另一扇同应用窗口。
- 列表尺寸供辨认；执行器接受请求时才固定参照状态、物理可见矩形、屏幕环境及桌面 GUID。读取后再次校验，之后在源窗口激活后、每次修改前和完成时复验。
- 身份、桌面、参照位置/大小/最大化状态、目标屏幕/DPI/配置变更会停止本次操作。目标小于 240 × 160 或部分超出其屏幕工作区时拒绝，不自动裁切、迁移或使用旧布局兜底。
- 允许跨屏参照及普通/最大化源窗口。沿用原有按屏幕复验、跨 DPI 修正与一次正常前台请求，不强抢焦点或主动切换桌面。
- 取消、Esc、外部失焦、重复入口、触发键释放和共享 pending/设置/其他选择器保护沿用。搜索不提交，模式切换重新等待输入就绪。

## 恢复与历史

与旧单窗放置共用执行器、真实修改前快照、700 ms pending、最终读回和一次 Undo。无变化及修改前失败保留原 Undo；已发生源窗口修改则保留单窗恢复；发出修改后无法确认最终状态时保留安全恢复快照并明确提示。可读最终状态优先于中间观测。

借用位置及其单窗恢复不发布、更新或清除历史布局位置，也不更改最近窗口组。不增加全局动作、配置项、持久化、固定屏幕分区、交换或窗口联动。

## 验证与边界

实现任务和验证证据见 [任务 01](issues/01-borrow-current-window.md)。原有真实输入阻断继续单独记录；受控窗口几何、注入故障和界面截图不能替代快捷键到源窗口前台的真实输入验收，也不能替代物理混合 DPI、显示配置和虚拟桌面切换验证。没有新的真实任务耗时或效率结论。

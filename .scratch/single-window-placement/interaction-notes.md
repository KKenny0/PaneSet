# 单窗放置：交互重新澄清

## 本轮目的与授权范围

用户已暂停此前的交互测试，并明确反馈当前“先把鼠标移到参照处，再按放置快捷键”的操作难以理解。本轮使用 grill-with-docs 澄清交互并记录决定；不启动实现、原型或测试。

## 已确认的目标

用户在“放进已有布局的一格”与“完全匹配任意参照窗口的位置和大小”之间回答“我想要第一种”。本轮围绕前者设计。

这里的“格子”沿用 GLOSSARY.md 的“布局位置”：成功整组排布分配的位置和大小，与后来的具体占用者相互独立。既有单窗放置边界继续作为讨论基础：只调整源窗口，原占用窗口留在后面，其他窗口不重排。没有产生需要新增的领域术语。

## 与旧规格的关系

spec.md 曾明确把“拖动吸附/标题栏手势”列为范围外。用户在本轮 Q1 回答“是”，接受以“拖动窗口标题栏，看到目标位置预览，松手放置”为主要入口。这确认了讨论范围扩展到拖动入口；尚未授权实施，也未取代已提交程序的行为。保留原规格作为历史依据，不将其改写成已实施的新方案。

此前“先移动指针、再按快捷键立即借用参照窗口位置”的偏好，已被用户后续的明确负面反馈取代，不能作为本轮入口的批准依据。

## 本轮已确认的交互决定

- Q1：用户回答“是”，接受 A「连续拖动」作为主要入口：按住源窗口标题栏拖动，看到目标布局位置的放置预览，松手后调整源窗口的位置和大小。此回答不确认吸附触发区域，也不授权实现或测试。
- Q2：用户明确选择“按住才启用”：以持续按住辅助键启用布局投放，不采用按一次快捷键切换模式。按推荐流程，拖动时按住辅助键显示布局，保持辅助键并松开鼠标完成投放；不按辅助键为普通拖动。具体键位尚未确认；目标命中范围见 Q3。
- Q3：用户回答“是”，确认启用布局投放时，以鼠标指针所在的布局位置为目标，整格内可命中并显示放置预览；不按源窗口边缘或覆盖面积判断，不要求瞄准中央标记。
- Q4：用户回答“是”，确认拖动途中先松开辅助键即退出投放：预览收起，继续普通拖动，此后松开鼠标不执行 PaneSet 投放；不自动回到拖动开始前。
- Q5：用户接受推荐：辅助键默认单键 Shift，设置中可自定义其他单键或组合键；不做连击后按住的节奏检测。按住检测不占用全局快捷键注册位。
- Q6：用户选择 A：格子来自内置布局模板，按住辅助键时套在当前屏幕工作区现算，冷启动即可用；不使用“最近一次成功整组排布”作为格子来源。影响：
  - 旧规格首轮决定 1“使用 PaneSet 已排布局的位置”对本拖动入口不再适用，属明确范围变化；格子与排布历史解耦。
  - 术语更新：GLOSSARY.md 新增“投放分区”，并把“单窗放置”改为放入投放分区，不再限定“已排布局中的某个位置”；“布局位置”仍保留给整组排布语义。
  - 旧规格中“最近成功布局位置记录”是否还需要、快捷键+位置图入口是否保留，另行确认，不默认共存。
  - 若所选模板与用户此前用 PaneSet 排过的同种布局在同一屏幕，套同一布局引擎会重现同样的格子；手工微调不反映。
- Q7：用户认为拖动中切换模板的几种交互（数字键、设置、滚轮）都不好，并提出可以不支持“拖到一半换分区方式”的场景；助手同意。决定：拖动中不切换模板，也不在拖动循环里检测数字键；当前生效的模板在拖动之外确定，方式见 Q8。
- Q8：用户回答“是”，确认首版采用“设置里选默认模板 + 模板词表借鉴 Loop”（预览与方向选择已在既有设计中）；循环粒度手势不入首版，待真实试用后若“分区不合意”高频再考虑，届时需重开 Q7 结论。不采用绑定主面板布局选择的方案。
- Q9：用户接受五个内置模板：左右两栏（1:1）、三等分栏、主辅（左 2/3 + 右 1/3）、上下两栏、2×2 网格。反向变体（如 1/3 + 2/3）暂不收录，试用后按需补。默认值与设置项定位随后由 Q10 修订。
- Q10：用户回答“是”，确认采用“分区先出 + 模板缩略图条备用”：按住辅助键拖动时，上次用过的模板的格子直接出现；屏幕上同时显示五个模板缩略图，指针划过哪个即切换并保持；不额外设设置项，记住上次选择。Q7 相应修订为“不提供需记忆的切换机制，但允许划过可见缩略图换模板”；Q8 的“设置里选默认模板”被海汰。缩略图条位置与尺寸、上次选择的记住范围（进程内或持久化）待后续小项确认。
- Q11：用户回答“是”，确认跨屏时格子只在鼠标指针当前所在的屏幕现算显示，指针移屏即换屏重算；源窗口所在屏幕不影响，松手落在指针所在屏的格子，不为目标屏另设状态。
- Q12：用户回答“是”，确认拖动中按 Esc 沿用 Windows 自身取消：整次拖动取消，窗口回到拖动开始前位置；PaneSet 只收起预览，不额外处理，不改变既有恢复记录。与 Q4 的区别已向用户说明：Q4 退出投放后窗口停在松手处，Esc 取消整次拖动。
- Q13：用户回答“是”，确认恢复语义：投放实际改变窗口后，用本次单窗恢复替代旧恢复记录（沿用现有一级恢复、实际改变才替换的规则）；恢复目标为拖动开始那一刻的位置、大小及正常/最大化状态，不是松手前的中间位置；无实际变化不替换旧记录。
- Q14：用户回答“是”，确认源窗口资格沿用现有合格窗口规则（普通可调整大小顶层窗口，含最大化；排除 PaneSet 自身、最小化、隐藏、工具/附属、全屏及其他虚拟桌面窗口）；不合格窗口拖动时按住辅助键不显示格子，也不弹提示。
- Q15：用户回答“是”，确认彻底搁置旧的“快捷键+位置图”方案（从未实施），拖动投放作为唯一单窗放置入口；“最近成功布局位置记录”概念随之取消；旧 spec.md 留作历史，真实使用后确有纯键盘场景再重开。
- Q16a：用户决定不把模板选择做成持久化偏好：上次模板仅进程内记住，退出清空，重启回到默认“左右两栏”。理由：选哪个模板通常取决于当时桌面的窗口打开状态，跨重启记忆意义不大。
- Q16b：用户回答“是”，拖动前已按住辅助键同样生效，按住状态为准，与起手顺序无关。
- Q17（新补充，待展开）：用户提出 PaneSet 窗口关闭或收起后不在任务栏保留按钮，只在通知区域（托盘）留小图标；进程与恢复记录照旧。这改变现有“没有托盘、任务栏是常驻入口”的边界，属独立小功能，与拖动投放分开；拖动投放规格已发布，随后定完 Q17。
- 规格发布：用户确认 seams 与落盘方式后，spec.md 已按 to-spec 模板重写为拖动投放规格（ready-for-agent，未授权实施），旧选择器方案保留在 git 历史。

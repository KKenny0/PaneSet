# 单窗放置：最小实施规格

Status: ready-for-agent
Progress: planned

基线：`eadec9b6aa1a40ae09b70c08ed2f433f6dad582b`。本规格是本轮收敛的实施建议，尚未实现、测试或发布；`ready-for-agent` 表示内容可供实现，不表示获得了编码或提交授权。用户已确认的决定与本轮新收敛的细节分别列出。

## Problem Statement

用户已排好主辅窗口，后来打开一个临时窗口，通常先用鼠标拖到辅窗位置，再选择保持原大小或手动拖拉缩放。目标是把定位和按需缩放合成一次位置选择，保持其他工作窗口的位置和大小。

证据为用户日常操作自述；未测量节省的时间，也没有竞品同任务实测。返回原任务的步骤尚未记录，不据此声称效率优势。

## Solution

在要放置的窗口上按默认 `Ctrl+Alt+3`，打开小型布局位置图；点击一个位置或按对应编号，立即把该窗口移动并缩放到那里。原窗口留在后面，其他窗口不重排；Esc 或外部失焦取消。

### 已确认的四项决定

1. 首轮使用 PaneSet 已排布局的位置，不识别任意手工摆放的布局。
2. 新窗显示在前，原位置上的窗口留在后面，不交换、不移走其他窗口。
3. 位置与大小使用上次成功排布的结果，不跟随之后的手工微调。
4. 实际改变窗口后只保留这次单窗恢复，替代之前的整组恢复记录，不提供连续撤销。

### 本轮收敛的实施选择

- 增加一个可改绑的全局动作，默认 `Ctrl+Alt+3`，并提供主面板备用按钮。
- 主面板、A、B 共用一份“最近成功布局位置”记录，进程内只保留一份。
- 源窗口可在另一屏，目标固定为该记录的原目标屏；选择器明确展示源标题和目标屏幕，不随鼠标切屏。
- 原成员关闭不使位置消失；整组恢复实际改变窗口后清除此记录，单窗恢复保留它。
- 环境失配就停止本次操作，不迁移旧坐标。以上为本轮实施建议，不冒充用户已逐条确认的历史决定。

## User Stories

1. 作为用户，我希望直接处理触发入口前正在操作的窗口，以便省去再次找窗和勾选。
2. 作为用户，我希望看到已有布局的位置和编号，以便按空间位置选择。
3. 作为用户，我希望一次选择同时应用位置和大小，以便减少手动拖动和缩放。
4. 作为用户，我希望鼠标和键盘都能选择位置，以便沿用当时的操作方式。
5. 作为用户，我希望新窗口在前、原辅窗留后，其他窗口保持原位，以便保留已布好的工作环境。
6. 作为用户，我希望临时窗口来自另一屏时仍可放到明确显示的原目标屏，以便跨屏使用资料。
7. 作为用户，我希望取消和无变化操作保留旧恢复记录，以便已有恢复能力不被无效操作替换。
8. 作为用户，我希望移动、缩放或退出最大化后即使发生失败，仍能恢复实际改变的窗口。
9. 作为用户，我希望原辅窗关闭后仍可使用它原来的布局位置，以便位置不依赖旧窗口继续存在。
10. 作为用户，我希望屏幕或桌面不匹配时明确停止，以免窗口被移到错误位置。
11. 作为用户，我希望快捷键冲突只影响这一个入口，以便其他快捷键和备用按钮仍可使用。
12. 作为用户，我希望原有自定义快捷键和外观设置在升级后保留，以免增加一个动作就重置已有配置。

## Implementation Decisions

### 1. 快捷入口与备用入口

- 新增动作 `PlaceWindow`，动作编号为 5；默认 `Ctrl+Alt+3`，含义为“单窗放置”，不改变现有四项默认值，也不改写用户当前自定义绑定。
- 设置中与已有动作一样支持改绑、禁用、恢复默认，以及保存值与实际注册状态反馈。默认键可能被外部程序占用，不保证注册成功。
- 全局触发时，在显示任何 PaneSet 界面之前捕获源窗口的完整身份；不把主面板或选择器变成源，不根据鼠标位置或最近使用顺序猜另一扇窗口。
- 主面板增加“单窗放置”按钮，使用本次启动或显式唤起主面板前已捕获的合格外部窗口，按钮旁显示源标题。此源记录仅属于本次面板唤起；收起面板或转到外部应用后清除。无合格来源时禁用并提示先从目标窗口唤起面板，不把列表任意已选项当作来源。
- 主面板按钮进入选择器时冻结源身份，随后收起主面板不清除这次已冻结的请求。此备用入口让新全局键失效时仍可通过现有面板键使用功能。

### 2. 位置选择与取消

- 小型位置选择器展示源标题、原目标屏名称、按真实比例绘制的布局位置和编号；不展示窗口总览，不要求再次选择源，也不提供布局切换或屏幕切换。
- 选择器显示在源窗口所属屏幕，尺寸限制在该屏工作区内；图中表示的是记录的目标屏布局。跨屏时明确显示“放到显示器 N”。
- 原有位置按成功排布时的成员顺序编号；只提供实际参与排布的矩形，网格最后一行未分配的空位不作为新位置。
- 点击位置、独立按下无修饰键的 `1` 至 `9`，直接提交对应位置，不增加确认页。位置 10 及以上通过点击或 Tab / Shift+Tab 导航后按 Enter / Space 提交，不解析多位数字；不存在的编号不执行。
- 初始焦点在选择器容器，Enter / Space 只有在位置按钮取得焦点时才提交。全部位置须可点击或滚动/键盘到达，不因窗口多而隐藏尾项或无限缩小点击区域。
- 全局和弦的全部按键松开、选择器取得真实前台和键盘焦点后，才接受一次新的位置按键；忽略按键自动重复。触发用的 `3` 不得穿透成位置 3，也不把点击传给源应用。
- Esc、取消按钮、点击外部应用导致的失焦，以及再次独立触发本动作，均关闭尚未提交的选择器，不移动窗口、不替换 Undo。再次触发不重新捕获源；一次请求只提交一次。
- 选择器未取得前台或键盘焦点时直接结束并显示非激活反馈，不采用输入模拟或持续抢前台。

### 3. 最近成功布局位置记录

- 记录与“最近窗口组”和 Undo 分开：它保存位置而非当前占用者，也不是恢复快照。原成员关闭、改标题或手工移动不重排位置，也不匹配同应用新窗口来替换成员。
- 主面板、A、B 的整组操作都可产生记录。仅最终整组成功时发布，包括无几何变化的成功；pending、部分成功或失败保留之前的记录，取消和预览不写记录。元数据采集失败时，保留原记录并说明本次位置未能记住，不把成功排布改报为布局失败。
- 每份不可变记录含：排布版本标识、按成员顺序的目标矩形、原目标显示器设备名及运行期标识、显示器完整物理区域和工作区、有效 DPI、显示配置代次、排布所在虚拟桌面 GUID。
- 坐标统一为整组排布现用的 DWM 可见边框物理像素坐标，含既有间距；不保存 WPF DIP，不复制外框坐标，也不在单窗入口重新跑布局算法。目标至少 240 × 160，完全位于记录的工作区内。
- 显示器标识校验不只比较 HMONITOR：同时检查设备名、配置代次和环境数据，避免拔插后句柄复用。显示拓扑变化使旧记录失效；工作区或缩放变化同样要求重新整组排布，不自动适配旧矩形。
- DPI 必须反映目标屏有效缩放，采样时使用 PaneSet 自有的每屏 DPI 感知窗口上下文，不把任意外部窗口的 GetDpiForWindow 返回值当作屏幕 DPI。采样不得激活或移动业务窗口；无法可靠读取就停止位置记录或本次放置，不跳过校验。可复用自有隐藏窗口完成采样，不引入第三方服务。
- 单窗放置和单窗恢复均保留这份位置记录，也不更新或替换最近窗口组。整组恢复只要实际改变任一窗口的位置或显示状态，就使位置记录失效；失败且无实际改变则保留。恢复记录需标明其来源为整组排布或单窗放置，避免混淆。明确退出清除全部进程内位置记录，重新启动需先排布一次。

### 4. 执行边界

| 情况 | 首轮行为 |
| --- | --- |
| 无成功布局记录、退出重启后 | 不打开可执行位置选择，提示“先用 PaneSet 排布一次窗口”；不生成默认布局。 |
| 原布局窗口已关闭或少于两扇 | 位置仍可使用，不要求旧组成员齐全。 |
| 源本来就是原组成员，或已位于选中位置 | 允许；确认无位置/显示状态变化时保留旧 Undo，仅激活和改变前后层次不算几何修改；无法读回实际影响的终局例外见下文。 |
| 源在另一块屏幕 | 允许移到记录的原目标屏，选择器先展示该目标；恢复回这次操作前的源屏。 |
| 源不合格、关闭或身份改变 | 拒绝；不换成同应用另一窗口。沿用现有普通/最大化可调整大小顶层窗口资格，排除自身、最小化、隐藏、工具/附属、全屏及其他桌面窗口。 |
| 源或选择器离开当前虚拟桌面 | 取消或拒绝。执行前同时验证源属于当前可见桌面、源桌面 GUID 等于布局记录 GUID；只比较 GUID 不足以允许执行。查询失败也拒绝，不移动窗口或切换桌面。 |
| 原目标屏消失、设备/配置代次/区域/工作区/DPI 失配 | 停止，不转到源屏、主屏或鼠标屏，不平移/缩放旧坐标；提示重新整组排布。 |
| 原记录在另一虚拟桌面 | 本次不可执行，记录可保留；用户返回匹配桌面后仍需通过全部校验，不自动转桌面。 |
| 应用不接受目标尺寸、权限不足 | 反馈实际失败或部分完成；已改变则保留本次单窗 Undo，不自动提权或换成近似布局。 |
| 第三方置顶窗口或应用自行联动其他窗口 | 不修改其他窗口的置顶、最小化或几何属性，不承诺覆盖系统置顶层级或阻止应用自身联动；按兼容性问题记录，不扩大 Undo 到整张桌面。 |

### 5. 执行、反馈与恢复

- 主面板协调入口、选择器及反馈；WindowManager 继续统一持有原生执行、pending、实际影响判断和 Undo，同时管理最近成功布局位置，避免界面和原生层各维护一份独立状态。
- 增加只接受一个明确源身份、记录版本和位置编号的单窗执行路径。旧整组入口仍要求至少两扇，不为复用布局算法伪造第二扇窗口或放宽所有整组资格。
- 提交后先关闭选择器并普通激活源。源身份仍有效且实际前台确为源，才进入几何修改；未取得前台则反馈未放置，保留旧 Undo。无需输入注入或永久置顶。
- 在第一次退出最大化、移动或缩放之前读取最新源状态、来源屏幕和 WINDOWPLACEMENT，不使用打开选择器时的旧快照。首次修改前及后续每个会改变状态的步骤前，再校验身份、当前桌面、来源/预期目标上下文和目标环境。
- 正常窗直接放置；最大化窗先恢复正常再放置，恢复最大化本身就属于修改。可见边框到外框的换算、跨屏后的边框处理与成功读回沿用整组操作的坐标合同；只有读回达到目标可见矩形且不再最大化才算位置成功，不为让测试通过放宽断言。
- 位置成功后复验源的前台状态。执行中被外部应用夺走前台时，不反复抢回，分别反馈“位置已放置”和“未保持前台”；不能把前台失败说成没有移动。普通窗口层级下新窗在前，原窗留后；不修改其他窗口的层级属性。
- 无变化、修改前失败和取消保留旧 Undo。只要源的位置或显示状态实际变化，即使最后失败，也用本次源快照替换旧 Undo；仅调用过 API 不足以判定改变。尤其覆盖“已退出最大化但定位失败”。
- 已发出修改请求但结果尚未确定时，继续保留修改前源快照并由共享 pending 管理，不提前报告无变化。终局读回仍失败且源身份仍匹配时，沿用现有执行器的保守规则：以本次源快照建立“结果未能确认，可尝试恢复”的单窗记录并替代旧 Undo；这是无法确认实际影响时的明确例外。身份已失效且无法确认改变时，不向新身份写入或建立可执行恢复，保留原 Undo 并明确提示本次未能记录可恢复结果。
- 恢复沿用现有快捷键及按钮，只还原本次实际改变的源窗口及原先正常/最大化状态；失败可重试，身份失效跳过，不替换错误窗口。恢复成功不会重新暴露之前的整组恢复记录，也不保证恢复焦点、前后层次或完整桌面。
- 源当前位置所属显示器的工作区/DPI 及原来源环境在恢复时也需校验；环境已变化时保留失败记录并反馈，不自动迁移坐标。既有整组恢复合同保持，不借本功能扩大支持范围。
- 所有入口共用一个忙碌/pending 保护。选择器打开时 A/B、恢复、设置与整组排布不能启动冲突修改；普通打开面板命令只指向现有选择器。设置已打开时按已有规则显示设置，不新建选择器。原生等待时任何入口都不能覆盖本次源、位置记录或恢复记录。
- 沿用 700 ms 的“正在等待”反馈阈值，不把它当取消；提交后的 Esc 不撤销已发出的请求。退出沿用已有 pending 风险提示，迟到结果不复活已退出界面或记录。

### 6. 配置兼容与改动范围

- 保持配置版本 1，在动作集合中增加可选的 `PlaceWindow`；显式 null 为禁用。有效旧文件缺失此动作时，默认启用新键，前提是不与已有有效动作重复；若默认键恰是某项旧自定义绑定，新动作在内存中禁用并提示改绑，原四项绑定及主题原样保留，启动不写配置。
- 配置内默认冲突与外部程序注册冲突分别反馈。外部占用时保留保存值但标为未生效，只影响新动作，备用按钮仍可用；已有注册不受影响。设置的显式重复组合仍拒绝，注册/保存失败保留原绑定，沿用已有事务，不自动找替代键。
- 标签和动作分发必须显式处理五个动作，不能让新值落入现有“其余就是 B”的分支；既有动作编号保持不变。
- 不持久化布局、窗口身份或 Undo。若在新版本中主动保存了新动作，旧二进制可能无法读取含新枚举键的文件；回退前使用保存前配置副本，或仅移除 `shortcuts.PlaceWindow` 后再启动旧版本，保留其他字段。此为明确的人工回退步骤，不自动覆盖用户配置。
- 复用现有主面板、WindowManager、快捷注册/配置/设置、Native 和主题资源，增加一个轻量位置选择器。预计连同测试触及超过 8 个文件；只改本功能需要的路径，不顺带提取整个排布协调器或重写 B 总览。

职责关系如下，选择器只回传选择，不持有自己的 Undo：

```text
全局动作 / 主面板按钮
          ↓
      主面板协调 ──→ 位置选择器 ──→ 回传位置编号
          ↓
  WindowManager：位置记录、单窗执行、pending、Undo
          ↓
     现有 Windows 原生操作
```

## Testing Decisions

以已有 WindowManager + 独立 FixtureHost 的行为检查为主要测试边界，通过真实窗口的位置、状态和恢复结果断言；补少量主面板/选择器的命令级检查和临时配置检查。不为每个私有方法新增镜像测试，也不通过真实工作窗口做自动检查。

| 计划新增单项 | 必须证明的外部行为 |
| --- | --- |
| `placement` | 主面板/A/B 均发布正确位置；同屏和跨屏普通/最大化源使用同一坐标合同；其他 fixture 窗口不动；原成员关闭后仍可放置；原组成员和原地无变化可用。 |
| `placement-guards` | 无记录、源关闭/身份复用、目标设备/配置代次/区域/DPI 失配、桌面不当前或 GUID 不符、查询失败均在修改前拒绝；执行中环境变化停止余下步骤且不换目标；grid 空位不出现。 |
| `placement-undo` | 单窗实际改变替代旧整组恢复；无变化/取消/激活失败保留旧恢复；退出最大化后定位失败可恢复；修改请求后读回失败但身份有效时发布结果未知的单窗恢复，身份失效不写新窗口；恢复失败重试；整组恢复有实际改变才清位置记录，单窗恢复不清；零改变失败保留记录。 |
| `placement-flow` | 正确捕获源、主面板备用来源、点击和独立数字提交、位置 10 以上导航可达、和弦释放/自动重复不误提交、Esc/失焦/重复入口取消、pending 互斥、激活失败不移动；源前台与位置结果分开报告。 |
| `placement-settings` | 旧文件缺字段、默认与旧自定义重复、外部注册占用、显式禁用、改绑/保存失败、恢复默认、重新启动和退出释放；四旧键和主题保留，启动不重写配置；新动作标签及分发正确。 |

共享回归重点为现有 `screen-arrange`、`screen-guard`、`recent-group`、`recent-group-noop`、`recent-group-failures`、`shortcut-settings`、`settings-binding-replace`、`settings-ui` 和 `maximized`，实施后按实际改动补齐同类路径。

真实输入和合成消息路由分别报告。输入自动化只允许操作本次受控宿主或 fixture，沿用当前前台/焦点/按键/严格鼠标命中保护；守卫失败即停止，不提高重试次数或降低断言。历史 quick-input 间歇调查继续暂停，不因新规格重开追查。

人工验收用三窗主辅布局加一扇真实临时窗口，验证呼出、选择、位置/大小、旧辅窗留后、取消、恢复与连续再次放置。跨不同 DPI 屏的最大化放置和恢复、选择器期间切换桌面/改变显示设置、管理员窗口或最小尺寸受限应用分别记录。缺环境写未运行，不把元数据注入当作物理环境通过。

## Out of Scope

任意手工布局识别、多份或持久布局、自动加入新开的窗口、拖动吸附/标题栏手势、直接把各位置绑定成一组全局键、自动交换/最小化/挪走原辅窗、把新窗加入最近组、连续撤销、联动缩放、应用启动、自动提权、跨虚拟桌面搬窗、显示变化后自动迁移、macOS、安装器及发布。

## Further Notes

### 实施与验证入口

本功能作为一个完整增量交付，入口、位置记录、原生执行与 Undo、配置兼容、检查同时落地；本轮不拆成半可用的默认全局动作，也不创建实现任务或启动编码。

现有验证脚本支持 `--case`。实施后注册以上五个计划单项，再运行对应命令，例如：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 -Check --case placement
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 -Check --case placement-guards
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 -Check --case placement-undo
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 -Check --case placement-flow
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1 -Check --case placement-settings
```

以上是待实现后的验证入口，现在尚不存在这些 case，本轮没有运行产品测试。未来实施后的完整回归沿用现有保护，运行一次并保留失败、不可用和未运行项，不将定向通过拼成全套通过；历史 quick-input 不进行重复定向追查。输入保护与实际桌面安排应先满足，再启动完整检查。

最脆弱的假设是已有位置图足以让用户快速选对目标。实施后用同一 T3 任务观察是否还需手工修补、是否比直接拖动更顺手；若位置选择本身更费事，调整入口和选择呈现，不扩大成工作区管理器。尚无实测效率结论。

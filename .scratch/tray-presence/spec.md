# 托盘常驻小图标：实施规格

Status: ready-for-agent
Progress: implemented

基线：`47cb48bff7c830c467c3268568a08ab2e13e7756`（feat/windows-two-window）。本规格基于同目录 [interaction-notes.md](interaction-notes.md) 的已确认决定；`ready-for-agent` 表示内容可供实现，不表示已获得编码、提交或发布授权。

## Problem Statement

PaneSet 目前把任务栏按钮作为收起后的常驻入口：窗口关闭或收起后，任务栏上一直留着一个按钮。用户不希望工具类常驻程序占据任务栏位置——任务栏是留给正在使用的窗口的。用户希望 PaneSet 收起后只在通知区域留一个小图标，任务栏保持干净；打开面板时一切照旧。

## Solution

打开的 PaneSet 窗口行为不变。关闭或收起后，主窗口完全隐藏：任务栏不再显示 PaneSet 按钮，只在通知区域保留一个小图标。进程、恢复记录、最近窗口组照旧保留。左键单击托盘图标打开/收起主面板，与现有全局唤起等效；右键菜单提供"打开面板、设置、退出"。"退出"仍真正结束进程并清除记录，待完成操作时沿用风险确认。不做开机自启。

### 已确认的决定

1. 窗口关闭或收起后：任务栏无 PaneSet 按钮，通知区域保留小图标；进程与既有记录语义不变。
2. 左键单击托盘图标：打开/收起主面板，等效现有全局唤起。
3. 右键菜单：打开面板、设置、退出（退出含待完成操作的风险确认）。
4. 开机自启：维持不做。
5. "退出"的清除与提示规则沿用现状，常驻位置从任务栏换到托盘是唯一变化。

## User Stories

1. 作为用户，我希望收起 PaneSet 后任务栏不留按钮，以便任务栏只显示我正在使用的窗口。
2. 作为用户，我希望通知区域有小图标表明 PaneSet 仍在运行，以便知道恢复和快捷键仍然可用。
3. 作为用户，我希望左键单击托盘图标就能打开或收起主面板，以便不依赖键盘也能唤起。
4. 作为用户，我希望右键菜单能直达打开面板、设置和退出，以便常用操作一步可达。
5. 作为用户，我希望从托盘退出与从面板退出一样有待完成操作的风险确认，以免误退出丢失恢复记录。
6. 作为用户，我希望收起后进程和恢复记录照旧保留，以便现有使用习惯不受影响。
7. 作为用户，我希望 PaneSet 不开机自启，以便由我决定何时运行。
8. 作为用户，我希望打开的面板和设置窗口行为与现在完全一致，以便本变化不带来新的学习成本。

## Implementation Decisions

- 主窗口与设置窗口沿用现有隐藏/收起入口；隐藏时同时从任务栏移除按钮（窗口级任务栏可见性开关），收起仍保留进程与全部记录，语义与现状一致。
- 新增通知区域图标：使用系统托盘接口创建与销毁，随进程生命周期管理；明确退出和进程结束都移除图标，不留残影。不引入第三方运行依赖。
- 左键单击触发与全局唤起同一条主面板开关路径；面板已有焦点时仍为收起，不另写第二套开关逻辑。
- 右键菜单复用现有打开面板、打开设置与退出的动作入口；退出沿用现有待完成操作确认与记录清除流程。
- 重复启动唤起已有实例的行为不变；单实例互斥量与事件照旧。
- 不做开机自启注册、安装器或托盘气泡通知。
- 图标视觉与悬停提示（显示应用名）属设计细节，实现时按现有亮暗主题与图标资源统一处理。

## Testing Decisions

以外部行为为断言对象，沿用现有 `-Check --case` 验证入口：

| 计划新增 case | 必须证明的外部行为 |
| --- | --- |
| tray-presence | 收起后主窗口隐藏且任务栏按钮移除、进程与恢复记录保留；退出清除记录并结束进程；待完成操作时退出确认默认不退出；重复启动唤起同一实例。 |
| tray-presence-menu | 托盘菜单三项路由到打开面板、设置、退出；左键等效全局唤起；面板已有焦点时收起。 |

托盘图标在通知区域的真实出现、真实左右键点击与视觉细节属人工验收，不以命令级通过冒充。共享回归沿用现有单实例、快捷键与设置相关 case。本轮只发布规格，未运行任何产品检查。

## Out of Scope

开机自启、安装器、托盘气泡通知、托盘图标拖动到溢出区的特殊处理、面板与设置窗口的其他行为变化、托盘图标右键菜单以外的快捷操作、macOS。

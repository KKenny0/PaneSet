# 本屏窗口总览：三种组织方式

这是可抛弃的 HTML 交互原型，用于比较 B 选窗的信息组织。窗口、内容、几何和恢复记录都是模拟数据；不控制真实窗口。

打开 [window-overview-prototype.html](window-overview-prototype.html)，使用底部控件切换，也可使用 `?variant=A`、`?variant=B`、`?variant=C`。三方案共享候选、默认前台、选择顺序与状态，切换不重置选择；点击“重新进入 B”才开始新选择，B 的布局选项继续保留。

| 方案 | 取舍 |
| --- | --- |
| 1：统一网格 | 内容尺寸一致，8 个候选在 1440 × 900 视口内能同时浏览；先推荐比较此方案。 |
| 2：大内容浏览 | 更容易区分相近文档，但逐份浏览需要较多滚动。 |
| 3：空间分布 | 用示意位置提供线索，卡片互不遮挡；并非最终排布位置，也未实现通用空间打包算法。 |

点击卡片多选，点击已选卡片取消；编号按选择顺序递补。至少两扇且没有失效成员时，Enter 或排布按钮提交模拟布局；Esc 取消。搜索框/下拉控件的 Enter 不提交。Alt+1/2/3 切换排布方式；左右方向键可切换方案，输入框/下拉框内除外。

“内容预览不可用”的窗口仍可选择。“原型场景与模拟状态”中可以让第 2 个已选成员失效，此时禁止提交；取消失效成员后继续。可以在模拟排布后重新进入 B，再 Esc 取消，检查既有模拟几何和恢复记录不变。

## 本轮证据

Playwright 在三个方案中分别操作了多选、布局、Enter、Esc、重新进入、预览降级、成员失效与恢复；核对了切换保留选择和页面重新加载为新选择。未发生浏览器异常。1440 × 900、900 × 600 与 390 × 844 下均无横向页面溢出，捕获并查看桌面和窄视口截图。切换条与滚动内容使用分开的视口区域；三种尺寸均核对区域不重叠，小视口另验证候选点击、排布按钮实际命中和取消可达。窄视口是网页展示适配，不代表 PaneSet 新增手机支持。

截图分别为 `overview-A/B/C-desktop.png`、`overview-A/B/C-small.png`、`overview-A/B/C-narrow.png`；[审视记录](review.md)是同会话角色自查，工具未提供独立子代理。用户已接受方案 1「统一网格」，随后确认稳定卡片排序、右侧前移/后移和滚动搜索。HTML 尚未加入前移/后移操作，也未模拟真实桌面坐标排序；以上检查不覆盖这些新增规则。元数据保持 needs-review，不能视为最终原生交互验收。

Windows 能力与未验证项见 [DWM 调研](../../docs/RESEARCH_WINDOW_OVERVIEW.md)。官方提供实时缩略图关系；本轮尚未运行原生探针，不证明 WPF 合成、遮挡或第三方兼容。漏标记问题仍单独开放。本轮没有改动生产源码。

# 产品定义

## 用户已确认的需求

用户希望开发自己的窗口调节工具。最烦的场景是：已经打开很多窗口，想让其中两三个窗口互相对照，用 Loop 时需要逐个选中窗口，再分别调整位置和大小。

| 项目 | 当前决定 |
| --- | --- |
| 核心场景 | 从多个已打开窗口中，整理当前需要对照的两三个窗口。 |
| 近期平台 | Windows 优先，原因是当前开发环境为 Windows。这个决定取代此前的 macOS 优先顺序。 |
| 后续方向 | 保留 macOS 方向，尚未安排实现时间。 |
| 本轮任务 | 初次两窗交付后，用户反馈多显示器、快捷操作及更多窗口的问题；当前扩展为跨屏选窗、多窗布局及全局快捷键。实现结果见[验收记录](VALIDATION.md)。 |

## 工作名

本轮使用 PaneSet，目录为 `paneset`。名称表达把若干窗口作为一组处理，不限定为两扇窗口。它是助手为推进本地工作采用的工作名，用户尚未确认最终品牌名。

## 待验证的产品主张

无需预先配置工作区，快速选出眼前需要对照的窗口，一次安排它们的位置和大小。

这个主张来自用户的真实使用摩擦，但还没有通过原型或竞品实测验证。多窗口排布、保存布局和相邻窗口联动已有成熟产品支持，差异需要体现在整个任务的选择成本、焦点切换次数和修补工作上。证据见[研究依据](REFERENCES.md)。

## 当前交互

当前交互已覆盖至少两扇窗口的选窗、布局、应用和恢复。它替代初次交付的两窗与同屏限制；任务效率仍需要真实工作试用验证。

1. 通过快捷键或应用入口打开选窗面板。面板出现前的前台窗口默认已选中。
2. 用户继续选择需要对照的窗口。列表以应用名、来源屏幕和窗口标题区分每扇窗口，同一应用打开的不同窗口分别列出。至少两扇即可排布，不设固定的两窗或三窗上限。
3. 面板内展示整组布局预览，选择顺序对应布局位置。布局切换和位置交换在面板内完成，不增加独立的预览步骤。
4. 用户确认后，一次操作安排选中的窗口。取消预览时，不改变实际窗口位置。
5. 对照结束后，提供恢复上次排布的操作，恢复仍存在且身份匹配的受影响窗口。

被其他窗口遮挡的窗口应能从列表选中。最小化窗口、隐藏应用窗口、其他虚拟桌面的窗口和全屏窗口属于不同情况，不能用“被遮挡”一词混为一谈。

### 当前布局

| 场景 | 默认或可选布局 |
| --- | --- |
| 两份文档或两个版本比较 | 两窗等宽并排。 |
| 三份资料互相比较 | 三窗等宽并排。 |
| 主工作窗口配合两个辅助窗口 | 一扇主窗口，另外两扇上下排列。 |
| 多份资料同时参考 | 网格；自动布局在四窗以上默认使用网格。 |

默认采用自动布局，两三窗等宽并排，四窗以上使用网格。用户可显式切换等宽、一主多辅或网格；一主多辅按选择顺序将 1 号作为主窗口。多窗“轮换顺序”将首窗移到末尾。默认间距为 12 物理像素，预期矩形小于 240 × 160 时不执行，提示减少选择或改用网格。该阈值只防止明显不可用的布局，不保证所有应用接受该尺寸。

## 当前范围

当前覆盖当前虚拟桌面所有连接屏幕上的普通可调整大小窗口，允许跨显示器选择。布局目标仍是用户明确选择的一台显示器，所有已选窗口会集中排到该屏幕。列表标明来源屏幕，确认前显示目标屏幕和整组预览。

面板打开前的前台窗口默认已选中，并以其屏幕作为默认目标；不符合候选条件时回退到鼠标所在屏幕，从空选择开始。刷新与切换目标屏幕保留仍有相同身份的已选窗口及顺序。快捷键从其他应用唤起时重新捕获当前窗口，开始新的选择。

选窗面板只操作用户明确选中的窗口。列表使用应用名、屏幕及标题；应用图标和真实内容缩略图尚未实现。

当前形成完整的选窗、整组预览、应用、恢复流程，并提供 Ctrl+Alt+Space 唤起或收起、Ctrl+Alt+Z 恢复。快捷键冲突逐项提示，保留任务栏及按钮入口；收起保留运行，明确退出会清除恢复记录。持续联动缩放、保存长期窗口组、显示配置变化后的恢复和 macOS 实现留待后续。

### 恢复的含义

恢复以应用排布前刚刚读取的位置、大小、各自来源屏幕及显示状态为依据，而非打开面板时的旧状态。首次修改前保存整组选中窗口。仅恢复上次操作实际影响的窗口，操作前再次确认窗口身份；跨屏排布后分别恢复到各自原屏幕。

窗口关闭时，跳过该窗口并说明情况。系统或应用阻止恢复时，报告每扇窗口的结果。用户的一次操作不意味着系统底层提供原子事务，也不承诺重启应用、重建窗口或恢复整张桌面。

## 如何判断是否值得继续

用同一组真实窗口分别完成两窗和三窗对照任务。比较当前操作方式、Windows 原生排列及现有批量窗口工具，记录从开始找窗口到布局满意的完整过程。

| 观察项 | 需要记录的事实 |
| --- | --- |
| 选择目标 | 找窗口、消除同一应用窗口歧义所需的点击、键盘操作和时间。 |
| 调整布局 | 焦点切换、布局操作和窗口位置交换的次数。 |
| 修补结果 | 是否需要继续手动移动或缩放，是否发生误操作。 |
| 恢复 | 恢复受影响窗口是否省事，失败时是否知道原因。 |
| 重复使用 | 用户在实际工作中是否反复需要这条流程。 |

选窗面板本身也会产生操作成本。只有完整流程减轻了现有摩擦，才支持继续开发，不能只计算批量移动时少了几次快捷键。

## 大列表、局部布局键与最近组

以下 Q1、Q2 设计已按两个增量实施。实现与自动检查结果见[验收记录](VALIDATION.md)，人工键盘、中文输入法与显示环境变化仍有未验证项。

2026-10-10，用户反馈窗口选择区只能方便地查看约两行，并接受以下 Q1 方向：

- 窗口列表和搜索是主要区域，正常尺寸争取同时看到 6 至 8 扇窗口。
- 宽窗口采用左右分栏：左侧大列表，右侧布局选择和紧凑预览。
- 窄窗口折叠预览，保留列表及主要操作的空间。

随后用户确认 Q2 的收敛范围：**明确选组、面板内布局键、主动载入最近窗口组**。以上已在当前面板实现，沿用本文的选窗、排布与恢复规则；真实输入验收状态独立记录。

### 单面板与布局键

沿用同一个选窗面板，布局选项旁显示键位提示。首版采用 Alt+1 等宽并排、Alt+2 一主多辅、Alt+3 网格；这些固定默认键位已实现，真实系统输入检查与合成路由分别报告。按键只切换预览，Enter 或排布按钮才执行；输入普通数字仍用于搜索。保留自动布局、Ctrl+F 搜索、Alt+S 轮换、Esc 收起及已有两个全局入口，不新增全局布局键。

从其他应用普通唤起时，继续捕获合格的前台窗口开始新选择；不隐式载入最近组。面板已有焦点时，全局唤起键仍收起；重复启动仍只打开面板，自身已有焦点时保留当前选择。

### 最近窗口组

在同一面板提供一个明确的“调整最近组”按钮，有记录时可用。只记住最近一次整组排布成功的具体成员、顺序、目标屏幕和布局，记录仅在当前进程中保留；收起保留，退出清除。

载入时刷新候选并清除搜索筛选，以当前标题展示身份仍匹配且符合候选条件的成员，保留其相对顺序、目标和布局。载入与预览不移动窗口，也不覆盖恢复记录。成员失效时明确指出缺失项，保留有效成员供检查或补选；不自动替换为同应用其他窗口。有效成员少于两扇时禁止排布。

原目标屏幕不可用时，要求用户重新选择，选择前禁止执行，不自动回退到另一屏幕排布。原目标仍可用但工作区域改变时，读取当前区域、更新预览并显示当前目标，再通过正常排布确认。实际执行前再次校验身份、候选条件和目标环境。

只有整组最终成功才更新最近组；等待中的操作保留本次请求，收到最终成功结果后再更新，最终失败或部分失败保留之前的最近组。整组成功但窗口状态没有实际改变时，可更新最近组元数据，原恢复记录保留。最近组与恢复记录独立：每次实际修改仍读取最新快照，恢复最近一次实际受影响窗口；连续换布局后，恢复到上一次有实际影响的排布前，而非初次选组前。操作未完成时，载入、布局切换、排布和恢复共用操作保护。

### 交付与验证

按两个增量交付：先完成 Q1 大列表与局部布局键，再在同一面板增加最近组。各增量均进行 /check 范围审查及修复，完整输入验收仍有阻断。首版不增加独立弹窗、多组保存、自动取最前几窗、跨进程匹配或额外全局直达键。

近期复用的价值假设是用户会重复调整同一组窗口；由后续真实任务试用记录调用频率、完整操作次数和耗时。混合 DPI、第三方应用和实际全局按键路径仍按现有验收边界验证。本轮没有按未经证明的原因修改生产快捷键激活策略，也未认定历史输入不稳定已经修复。

实现规则和验收条件见[本地规格](../.scratch/multi-window-controls/spec.md)，竞品依据见[快捷交互调研](RESEARCH_SHORTCUTS.md)。

# Windows 两窗原型验收

本轮完成用户批准的两窗交付，代码和启动入口已落地。产品工作名仍为 PaneSet。

## 已实现

- 当前虚拟桌面和目标显示器内的普通可调整大小窗口列表，独立显示同一应用的多个窗口。
- 应用名及标题搜索、最多选择两扇窗口、选择序号、交换左右和整组几何预览。
- 修改前读取最新位置及显示状态，排布后读取实际结果，部分失败按窗口报告。
- 最近一次实际排布的恢复，包含原先最大化的窗口；关闭或身份变化的目标跳过。
- 后台同步系统调用，面板遇到延迟响应时保持可用，原操作完成前阻止冲突修改。
- 本地配置、局部 SDK、启动和验证入口。

## 实测环境与结果

环境为 Windows 10 Pro 22H2、19045、x64，可交互桌面有两台显示器。局部 .NET SDK 10.0.401 经过官方 SHA-512 校验，WPF 应用已实际构建和启动。布局计算以物理像素为单位，应用和验证程序声明 PerMonitorV2。

完整检查通过 16 项，构建为 0 个警告、0 个错误。验证使用独立进程创建的真实 WPF 顶层窗口；面板验证通过可访问性接口驱动真实控件，没有移动已有用户窗口。

| 两窗布局、负原点与奇数宽度、无效区域 | 通过。 |
| 同一应用的多个窗口枚举 | 通过。 |

| 正常状态恢复、最大化状态恢复 | 通过。 |

## 审查

以工程准备完成的 `main` 提交为实现基线，分别进行 Standards 和 Spec 人工审查。Standards 检查项目说明、领域术语和模块职责；Spec 检查已确认的两窗交付与两项测试边界。没有发现剩余阻断项。系统调用被限制在窗口管理模块，布局计算独立；面板和验证程序使用同一窗口管理接口。开始实际修改后，比较整组选中窗口与原始快照，保留发生变化且身份仍有效的目标，涵盖应用间接改变另一扇窗口的情况；恢复仍校验显示器和工作区域。

Advisor 进行架构和截图复核，推动补齐永久挂起与恢复重试验证、同一应用预览标题和长标题处理。该次工具没有附送项目源码，不能称为独立源码审批；本轮也没有并行双代理审查。

## 本轮边界

- 目前支持两窗并排，三窗、全局快捷键、跨显示器选窗和 macOS 尚未实现。
- 验证集中在当前主机上的受控 WPF 窗口，尚未系统测试浏览器、PDF 阅读器、管理员应用或其他第三方应用。
- 实测界面使用当前显示配置；混合 DPI、其他缩放比例、任务栏位于上方或左侧及显示器变化尚未进行实机验收。
- 位置恢复是逐窗操作，不能保证原子性。身份检查和关闭事件监测降低误操作风险，仍存在系统窗口操作固有的竞态。
- 恢复记录只保存在当前进程中，退出后清除。窗口一直不响应时操作仍待完成，面板保留等待状态；确认退出会丢失恢复记录，尚未完成的系统请求可能稍后生效。不能把超时或退出当成取消成功。
- 当前 Windows 10 Pro 22H2 不在 .NET 10 官方支持列表中。本轮是可运行原型，未作正式发布兼容性承诺。
- 尚未与竞品比较完整任务耗时，不能根据功能实现宣称产品更快或具有独创性。
